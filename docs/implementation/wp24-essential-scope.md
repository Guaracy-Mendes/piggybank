# WP-24 essential R1 acceptance scope

Scope decision: 2026-11-15. The user requested completion of the most important functionality through WP-24, with enhancements later, and an explicit stop before WP-25. The full [PRD](../PRD.md) remains the target product. This decision defines local synthetic acceptance; it does not certify production R1.

## Required for this completion

1. Retain the existing unique balanced GL export, authenticated simulator receipts/recovery, immutable reports/revisions, explicit liquidity freshness and owned reconciliation differences.
2. Publish separately approved financial enrollment terms derived from an exact approved calculation/calendar version. Preserve preview-only policies and historical preview acknowledgments without converting them into consent.
3. Obtain explicit sole-owner consent to those terms, retain the full material and attribution, permit withdrawal while pending, and require separate independent Finance approval for native Core activation.
4. Finalize each account's next complete closed UTC period using bounded native journal history. Core owns the clock, amount, counter account, economic uniqueness, immutable evidence and balanced financial receipt.
5. Execute monthly fixed fees and daily ACT/365 fixed credit accruals, including explicit zero completion. Enforce holds/restrictions, repair scheduling gaps, discover due work automatically, and recover one original receipt across retries/concurrent jobs.
6. Export resulting journals through existing GL controls; reverse eligible periodic postings only through exact-source independent approval and new linked journals. Preserve the original period basis.
7. Supply basic customer/staff web flows, typed API contracts, an operator runbook, C4/UML diagrams, and native/browser/regression evidence.

## Deliberately deferred

| Enhancement or qualification | Retained boundary / later acceptance |
| --- | --- |
| Non-UTC settlement calendars and DST transitions | Only UTC is enabled. Holidays, ISO weekdays, following roll within 14 days and cutoff equality are covered. Broader BR-15 qualification remains for provider/qualification work. |
| Product-specific legal/compliance certification | The approved material is explicitly synthetic TST. Real documents, jurisdictional review, retention/legal-hold policy and launch approval remain outside this acceptance. |
| Tiered/negative rates, taxes, proration, variable charges, compound product rules | R1 uses whole-month fixed fees and nonnegative daily closing-booked ACT/365 fixed credit accrual, half up each day. |
| Re-enabling a stopped or withdrawn enrollment | No resume command. A new independently approved policy/offer and fresh consent are required. |
| Large account history | More than 1,000 source journal facts refuses finalization; no truncation or substitute current balance. Production scale needs checkpoint design/capacity evidence. |
| Global accounting close / automatic prior-period restatement | Finality is an account-period watermark. Late actual receipts book on the current native bank date; provider value date remains evidence. Corrections affect later periods, preserving original closed facts. |
| Real providers, live AWS/GCP, NFR-14 operational SLA, security/capacity/DR and production R1 qualification | These retain the roadmap's separate gates. Local observations and simulator tests do not establish these results. |
| Additional UI polish and more channels | Functional review, consent, approval, posting evidence and recovery are required now. Statements, alerts, native mobile and later work packages are not started by this instruction. |

Completion means this finite scope is implemented and validated. It does not remove deferred items from the full target or make completion of WP-24 equivalent to completion of R1.
