# WP-22 — Evidence ingress, settlement, incoming funds and linked returns

Implemented and verified in the synthetic local environment on 2026-10-30. SIMULATED/TST signed HTTP callbacks now drive durable outgoing finality and incoming/return processing. The selected protocol verifies live HMAC authenticity and freshness before accepting evidence. Original authenticated packets remain immutable; later financial recovery independently checks archived integrity and exact financial scope. A `202` means durable acceptance for processing. File ingestion and actual payment-provider qualification are separate work.

Core settlement atomically consumes the original submitted hold, books principal and fee once, posts gross daily principal usage and records an immutable finality receipt. A later debit freeze does not discard the submitted commitment. Only authenticated definitive rejection/cancellation releases submitted funds. Acknowledgments and NOT_FOUND never suffice. Tests cover response loss after Core settlement, provider-confirmed cancellation, cancellation attempted after settlement, delayed acknowledgments and conflicting final outcomes. Financial receipts recover the same journal; a consumed hold cannot be released or generically reversed.

Incoming and returned funds first post clearing to controlled suspense. Payments derives the destination customer from Core, obtains current signed checks and presents a trusted bound allocation permit. Core rechecks the current destination under financial locks. Unknown references, closed/restricted destinations and review outcomes retain funds in suspense with owned cases. Repeated callbacks and lost allocation acknowledgments recover one suspense and one customer allocation journal. Customer inquiry reauthorizes actual account ownership; workforce inquiry requires current payment authority and payments queue membership.

Original-linked returns require an authenticated settled external payment. Their total accepted principal, including funds awaiting allocation, cannot exceed the original principal. Concurrent competing returns serialize under the original-payment lock. New linked journals preserve the original settlement, fee and gross daily usage. Tests accept partial/multiple returns through the exact cap and reject excess without changing balances. Provider evidence IDs cannot be reused across outgoing finality and incoming/return financial meanings. Authenticated conflicts are retained in immutable quarantine with owned Controls investigations.

The customer browser shows incoming availability only after Core allocation, original payment details, separate cumulative return totals and correction history. Only an unconfirmed unreserved DRAFT advertises immediate cancellation. The workforce browser shows original settlement and credit receipts, partial/full returns and safe quarantine summaries. The browser flow verifies forged callback rejection, duplicate acceptance, exact settled/returned/incoming balances and excess-return quarantine. Mobile and desktop screenshots were inspected; accessibility and mobile overflow checks passed.
