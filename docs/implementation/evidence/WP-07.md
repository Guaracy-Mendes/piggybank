# WP-07 — Audit and evidence storage evidence

Verified locally on 2026-10-23. `make test-integration` passed two real PostgreSQL integration suites and `make app-check` passed with warnings denied and generated-client checks.

Controls owns a protected append-only audit stream. A security-definer function serializes sequence/hash-chain updates, preserves event identity on equivalent retry and rejects conflicting reuse. Runtime principals cannot insert outside that function or update/delete/truncate the audit history/head; immutable-history triggers also reject owner-level record edits. Verification checks record digests, sequence, predecessor and head. Twenty concurrent appends produced a valid contiguous chain.

The restricted evidence service persists staged metadata, writes immutable opaque-ID objects with integrity digests and bounded reads, commits readiness with audit, and verifies owner/issuer before retrieval. The filesystem adapter uses private directories/files, refuses version replacement and rejects symlink traversal. Tests proved cross-subject denial, corrupted-content rejection, no replacement, symlink refusal, recovery after a durable object/write-before-metadata completion, and inventory of unreferenced objects. Unreferenced objects are not automatically deleted.

Filesystem I/O occurs outside database transactions and on a blocking executor. Recovery is attributable to a service identity. Shared test support creates isolated disposable databases, applies the same migration registry and never substitutes an in-memory database or silently skips missing dependencies.

These are callable domain/storage services, not an exposed evidence-download product endpoint. Case-specific staff authorization, retention/legal holds, external integrity anchoring and production object protection are later packages. Local hash-chain evidence does not claim resistance to an administrator rewriting the entire database and its anchors.
