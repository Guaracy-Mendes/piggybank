# WP-13 — Distinct control authority evidence

Verified locally on 2026-10-23 with `make test-integration`, `make test-ingress`, `make test-events`, `make migrate` and `make app-check`. Controls owns independent identity, sanctions, risk and fraud requests/results with stable provider identities, generation/input/policy binding, immutable evidence records, expiry and minimized outbox facts. Mandatory-gate composition never substitutes identity clearance for screening or payment fraud checks.

A separate persistent loopback provider process implements synthetic allow, deny, review, pending, timeout, accepted-but-response-lost, late and conflicting outcomes. Provider results use HMAC authentication bound to the document and fresh timestamp. Outbound calls have bounded response size/time, fixed local endpoint policy, no redirects and no held database transaction. The actual HTTP callback rejected forgery, accepted an equivalent result twice, and rejected authenticated conflicting evidence without overwriting history. Conflicts became review-required. Changed request scope, expired evidence and superseded callbacks were rejected and recorded.

Real process tests proved timeout stays pending, a lost response recovers the same accepted request/evidence, duplicate polling produces one immutable result and provider restart preserves identities. Evidence expiry produced a new request generation. The worker durably claims bounded polls, retains owned manual-review next actions after its retry/deadline budget, and schedules expired checks for reassessment. Audit/provenance records remain reconstructible; restricted evidence is outside broad events. Case ownership, information requests and manual disposition are integrated in WP-14.

These are explicit synthetic decisions and local shared-key contracts. Actual market policy, production key handling and external provider certification remain WP-31 qualifications.
