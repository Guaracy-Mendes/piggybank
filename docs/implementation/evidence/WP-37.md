# WP-37 completion evidence

WP-37 was completed on 2026-11-18 as migration `0071_governed_warehouse.sql` (schema 71). By user decision it is
**scoped to one local warehouse adapter** (`LOCAL_WAREHOUSE`), the template for later analytical storage and processing
adapters. See the [specification](../governed-warehouse.md), the [adapter contract](../../../infra/analytics/README.md)
and the [acceptance README](../../../tests/acceptance/analytics/README.md). Analytical products and regulatory report
formats remain pending selection (DEC-05, DEC-06, DEC-08).

## Delivered behavior

1. **Versioned governed ingestion.**
   - Two datasets (`ledger_entries`, `account_states`) with source field catalogues.
   - Version 1 contracts in `contracts/events/analytics/`.
   - Runtime registration of backward-compatible versions; incompatible proposals return 409.
   - Incremental ingestion by the worker every 30 s, with a 30 s safe lag; evidenced backfills by data stewards.
2. **Economic deduplication.** Facts are append-only and keyed by economic identity:
   - a replay or re-delivery under a new batch id is a duplicate;
   - different content for the same identity is quarantined, never overwritten;
   - invalid rows are rejected and recorded.
3. **Reproducible transforms and lineage.** `daily_ledger_movement` v1 and v2 each carry a definition digest. Immutable
   snapshots record:
   - the fact cut and master cut;
   - the schema versions, runs, transform, purpose and adapter;
   - a result digest.

   Reproduction recomputes at the stored cuts and records the outcome. Each row traces to its facts and source rows.
4. **Quality and control totals.** Snapshots raise these flags:
   - `MISSING_SOURCE`, `STALE_SOURCE` (uningested rows) and `MISSING_ACCOUNT_STATE`;
   - `ECONOMIC_CONFLICT`, `CONTROL_TOTAL_MISMATCH` (against Core's journal) and `UNRESOLVED_MASTER_CONFLICT`.

   Control totals compare four stages: Core, input, purpose exclusions and output.
5. **Purposes.**
   - Role and dataset checks, with denials recorded and audited.
   - WP-28 `ANALYTICS` restrictions exclude the party from optional analytics, never from mandatory financial
     reporting.
   - Reads re-check the purpose.
6. **History is never rewritten.**
   - Corrections arrive as new linked facts and are explained in the superseding snapshot.
   - Master conflicts are flagged with no automatic merge.
   - After an approved merge, later snapshots regroup while earlier ones still reproduce. Core ownership never changes.
7. **Core boundary.** `bank_data` has no usage on the `core` schema and no table privileges in `analytics`. No analytics
   function body writes Core or calls a volatile Core function.
8. **Clients.** Staff API (7 routes), the staff portal page **Governed warehouse**, and the
   `analytics.snapshot-published` event.

## Boundaries

- **Out of scope.** External analytical products, object storage, streaming, BI tools (DEC-08), regulatory report
  formats (DEC-06), audiences and insights (WP-38), and schema registration in the portal (API only).
- **Known limits** (see the specification):
  - A master-change transaction that straddles a snapshot's master cut shows up as a recorded reproduction mismatch.
  - Rejected source rows count as stale until corrected at the source.
  - Analytical retention is not yet scheduled.
