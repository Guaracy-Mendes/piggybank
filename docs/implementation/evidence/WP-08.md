# WP-08 — Durable operation/workflow evidence

Verified locally on 2026-10-23. Four real PostgreSQL integration tests, warning-free Rust/generated-client checks and the HTTP ingress/contract suite passed. The implemented contract now contains 12 route patterns, including protected customer/workforce operation-status resources.

Operations persist actor/client scope, stable identity, canonical request fingerprint, state/version and work in one transaction. Twenty concurrent equivalent requests produced one operation and one initial job. Changed payload under the same key conflicted, another subject could not retrieve the status, and an invalid job rolled back acceptance rather than leaving accepted work without continuation.

Jobs use durable availability times, owner leases, monotonically increasing fence values, bounded retries and explicit review-required exhaustion. Tests expired a worker lease, reclaimed it, rejected stale completion/retry, continued to another durable step, and completed exactly once. Equivalent completion acknowledgement retry was idempotent; changed completion content conflicted. Reconstructed service instances read the same persisted operation. Exhausted unknown work became review-required rather than a false financial failure.

Operation-status responses contain authorized workflow metadata, not cached domain records or an assertion of settlement. Domains must reauthorize before command/result replay, and external financial side effects require their own stable instruction/posting keys. Job leasing does not promise exactly-once external execution. Runtime dispatch/event transport follows in WP-09.
