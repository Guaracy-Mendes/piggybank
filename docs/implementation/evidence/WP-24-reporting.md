# WP-24 progress — Immutable Finance observations and liquidity

Verified locally on 2026-11-01. **WP-24 remains in progress.** This increment adds consistent Core snapshots, frozen Core/GL observation reports, exact controls/source pages, owned historical exceptions and independent signed synthetic liquidity to the [GL export slice](WP-24-progress.md). It does not complete full instruction/provider/fee reconciliation, approved report revisions or periodic fee/accrual automation.

Core captures journal membership, complete legs, account classifications, account stocks/holds and active outgoing principal in one bounded REPEATABLE READ, READ ONLY transaction. A real concurrent test posts twenty balanced funding commands while repeatedly checking that captured customer stocks equal the captured journal membership. Active external reservation tests verify that principal commitments and customer held totals, including fees, remain distinct. Half-open UTC periods are bounded to 366 days and 1,000 batches; a 1,001-batch test rejects the report without publishing truncated controls or changing balances.

Finance captures export/chart/receipt evidence in a separate consistent read and closes both database transactions before provider HTTP. Format-version-1 artifacts seal the original Core membership, full source lineage, source/item digests, account controls, exact debit/credit totals, matching GL totals, captured liquidity and completeness. Core/Finance/provider clocks remain explicit rather than claiming global atomicity. Matching requires original identity, business date, exact account values, effective mapping and authenticated receipt. Customer mappings must remain liabilities and settlement mappings assets even with account overrides. A new test proves that a valid signed GL booking receipt cannot conceal an incorrect customer-to-revenue classification.

Concurrent identical report requests return one artifact. Changed periods with the same actor/client/key conflict, and revoked authority denies replay. Earlier partial reports retain the same membership, totals, evidence status and digests after later bookings or fresh cash evidence. Detail retrieval reconstructs source/item membership digests and archived liquidity lineage. Source pages verify captured matching GL receipt integrity. Expired evidence changes derived current freshness without rewriting the captured report. Tables reject artifact/member/proof mutation.

Date/value/mapping/identity/receipt gaps remain explicit and excluded from matching GL totals. New processing windows stay visible as partial; mature gaps and conflicts have owned snapshot issue cases. Missing/stale/invalid liquidity creates whole-report observations. Immutable issue records precede recoverable case assignment. These cases describe the retained historical report rather than reopening a newer operational reconciliation result.

The independent provider has no default cash amount. It retains immutable versioned evidence, replies under a separate key with exact request-nonce/currency/scope binding and preserves original as-of/expiry. New stale or invalid versions cannot fall back to an older fresh version or a Core ledger balance. Current available liquidity remains unavailable without fresh authenticated evidence and recent Core commitments. Provider reserved/settled cash and expected incoming/outgoing remain distinct; expected funds do not increase available cash. The explicit conservative rule subtracts every Core active outgoing principal commitment from provider available cash and floors at zero; it does not authorize money movement.

The workforce view saves and reopens report URLs, shows exact controls and stable source pages, links owned exceptions and separates live cash from historical capture. The real browser flow saves a partial missing-feed report, publishes fresh independent evidence, saves a complete observation, confirms the original report digest remains unchanged and verifies stale cash becomes unavailable. It exercises a value above JavaScript's safe integer limit without rounding, same-key replay and changed-key-scope `409`, role denial, retained receipts, unchanged Core balances/journal count, desktop/mobile accessibility and mobile overflow. Both `.local/finance-report-workbench.png` and `.local/finance-report-mobile.png` were produced; the mobile layout was inspected.
