# WP-25 completion evidence

WP-25 was completed on 2026-11-17 as migration `0062_document_statements.sql` (schema 62), within its local synthetic scope. The [specification](../statements-retention.md), [runbook](../../runbooks/statements-retention.md) and [acceptance manifest](../../../tests/acceptance/documents/README.md) give the details.

## Delivered behavior

1. **Statements (FR-DOC-02).** Monthly UTC statements per account, built from native Core journals.
   - A statement is published only when the month has ended in Core's clock and every enrolled WP-24 periodic policy is finalized through the month end.
   - Totals are exact: opening, credits, debits, fees, interest, corrections and closing, with `closing = opening + movements` enforced.
   - Each version carries an immutable snapshot and content digest. Generation is idempotent and concurrency-safe.
   - A version supersedes the previous one only when the source changes: `LINKED_CORRECTION` (identical totals) or a visible `SOURCE_CHANGED`.
2. **Retrieval (FR-DOC-03).**
   - Each reference expires after two minutes and works once. Only its hash is stored, and it is bound to the actor.
   - Retrieval is denied for a foreign actor, a non-owner, an already-used or expired reference, a disposed object or an integrity mismatch.
   - Every grant, retrieval, denial and readiness refusal is recorded as append-only access evidence.
   - Customer and workforce routes are separate, and the PDF is rendered from the redeemed version.
3. **Retention, holds and disposal (FR-DOC-04).**
   - Versioned fixture retention policies cover statements, exports and access evidence.
   - Account and person legal holds use idempotency keys and require release by a different approver.
   - Disposal is restricted by retention, hold or policy. A permitted disposal writes evidence first, then removes the object, leaving a minimized tombstone.
   - Owner-path bypasses are refused by triggers.
4. **AT-16.** Verified access, correction and deletion requests produce per-record allowed or restricted outcomes and a retained outcome digest. Access exports are kept under their own retention policy.
5. **Clients.**
   - Customer: **Statements & documents** page.
   - Staff: **Records & retention** workspace.
   - Worker: a 60-second statement cycle that is fair across failing accounts.
   - API: OpenAPI and the generated client cover all 15 new routes.
   - Roles: `records.read`, `records.manage` and `records.approve` capabilities; the local seed grants the records roles.

## Failures before the final run

These are retained here, not hidden:
- **Renamed button.** The first consumer run failed one existing journey that used the old button name, "Create native statement". The selector was updated.
- **Missing fixture variable.** The first gated consumer run at offset 200 left onboarding in `CONTROLS_PENDING`. The isolated browser fixture had never set `BANK_SIMULATOR_URL`. Earlier runs had reached the provider on 4182 only because the preview happened to be running there. `tests/browser-customer/server.py` now passes the offset provider URL.
- **Superuser-only fixture.** A draft integration case used `session_replication_role`, which needs superuser rights. That readiness branch moved into the real periodic-finance test.

## Boundaries

The retention durations are synthetic fixtures. Real schedules, holds and certification remain DEC-06 and DEC-11 inputs. The following are deferred:
- objects are stored in PostgreSQL rather than a production object store or encryption/backup propagation (WP-28, WP-29, WP-31)
- notifications (WP-26)
- native mobile retrieval (WP-27)
- non-UTC or non-monthly cycles
- more than 1,000 facts per account-month
