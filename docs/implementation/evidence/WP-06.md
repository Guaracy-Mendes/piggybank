# WP-06 — API ingress and contract evidence

Verified locally on 2026-10-23. `make app-check`, `make test-ingress`, `make test-identity` and `make test-browser` passed after ingress integration.

Implemented bounded request bodies/timeouts, UUID correlation, safe JSON errors, security/cache headers, JSON API 404/405 behavior and PostgreSQL-backed ingress quotas. Two simultaneously running API instances shared an atomic quota; changing `X-Forwarded-For` did not bypass the socket-derived scope. Health remained available when the quota was exhausted. Oversized bodies were rejected before domain handling, and malformed callback/API-version requests exposed no internal diagnostics.

The OpenAPI document lists nine actual route patterns from the health, identity and API routers. The contract checker compares them with source declarations and rejects generated TypeScript drift. A typed `openapi-fetch` client uses BFF credentials without storing tokens; TypeScript checking passed. HTTP tests exercise every documented path and status boundary. Proposed banking resources are not published as implemented APIs.

The real issuer and Chromium authentication checks passed again through the gateway middleware. Production trusted-proxy topology, capacity, per-partner policies and deployment qualification remain later gates. Current budgets are local engineering defaults, not commercial rate promises.
