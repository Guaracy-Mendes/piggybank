# WP-17 — Servicing, snapshots and mastered references

Verified locally on 2026-10-23 with fourteen real PostgreSQL integration tests, current generated-client checks and the expanded real-OIDC HTTP lifecycle. The API now covers 42 actual route patterns, including accounts, authoritative balances, transaction history, freeze/closure, owned support and verified contact changes.

Core history materializes the selected movement identities inside a repeatable-read transaction, rather than relying on a timestamp cursor that could admit later commits. Cursors expire after fifteen minutes, retain the period/actor/account scope, and recheck current authorization on every page. Tests inserted new postings between pages and proved the original movement set had no omissions/duplicates; a fresh snapshot included the new posting. Period/page/item limits are explicit. Journal corrections retain their original batch links. Balance responses expose exact posted/held/available amounts, source and as-of time.

Contact changes are durable, independently verified workflows with separate input/version identities and control provenance. Original legal identity and accepted application evidence remain unchanged. Missing verification leaves the current value intact; a concurrent stale change requires review instead of overwriting a newer verified contact. Duplicate change keys are stable, altered content conflicts and other customers cannot retrieve the status. The local verification source is explicitly synthetic. Financial account restrictions/closure and support requests enforce current ownership, held value and obligations.

Data consumes Core facts through a narrow read-only source port. Inbox, versions and projection effects commit together; duplicates/gaps/conflicts/unsupported schemas are visible. Account/hold/transaction projections carry source versions/times, while spending and customer balances still use Core. Authorized replay repaired a quarantined version gap. Master-reference changes require current stewardship, independent details-bound approval, a related authorized case and integrity-checked restricted evidence, retaining immutable mapping history. A controlled enterprise alias changed no Core party, account owner or balance, and the Data database principal could not update Core financial tables.

The actual HTTP test exercised scoped balances/history, balanced idempotent fixture funding, owned support, freeze, residual-value denial, zero-value closure, contact verification, Core/Data projection convergence and process restart. The fixture's total ledger remained balanced. Browser/client views follow WP-18/WP-19; real verification providers, policy and production qualification remain external gates.
