# WP-27 completion evidence

WP-27 was completed on 2026-11-17 within its local scope: an Android emulator with a synthetic environment. iOS evidence is explicitly **pending**. Migration `0064_native_step_up.sql` brings the database to schema 64. The [specification](../native-mobile.md), [runbook](../../runbooks/mobile-development.md) and [acceptance manifest](../../../tests/mobile/README.md) give the details.

## Delivered behavior

1. **App.** `apps/mobile` is an Expo SDK 54 / React Native 0.81 app on the generated OpenAPI contract, with an isolated, exactly pinned lockfile and explicit root workspaces. Screens: accounts and authoritative balances, onboarding and application status, payments and recipients, statements, support and messages, and profile and device.
2. **Native authentication.** System-browser PKCE for the public `bank-mobile` client with a custom-scheme return and a verified nonce. Access tokens stay in memory. Refresh tokens rotate and are held in Keystore-backed secure storage (this device only, no backup). Sign-out and device removal revoke at the issuer and wipe local credentials.
3. **Native action-bound step-up.** New begin and proof endpoints. The server verifies a fresh ID token's audience, nonce, subject and `auth_time` before recording the same single-use proof as the browser flow. Browser sessions are refused on this path, and native-only customers are registered as subjects.
4. **Lifecycle and accessibility.**
   - Payment requests are persisted first and recovered from the same operation, never replaced.
   - Offline mode blocks commands with no queue.
   - A privacy cover hides balances in the background, and resume re-reads the server.
   - Controls are labelled, with roles and 48 dp targets, and content respects safe-area insets.
5. **Toolchain.** `scripts/mobile.sh` and the make targets `mobile-check`, `mobile-build`, `test-mobile-api` and `test-mobile`. Builds use a checksummed project-local Temurin 17; GraalVM is refused with a clear message.

## Failures before the final run

These are retained here, not hidden:
- **GraalVM `jlink`.** The first two Android builds failed because GraalVM's `jlink` breaks Android's JDK-image transform; Gradle toolchain detection also picked GraalVM 17. Resolved with a checksummed project-local Temurin 17 and auto-detection disabled.
- **Native-only step-up.** The first device run failed at step-up with HTTP 503. The cause was a foreign key from the step-up proof to the issuer subject: native-only customers had never been registered as subjects. The earlier HTTP test hid this because a browser login had already registered the subject. Fixed by registering the subject in the step-up transaction. The HTTP test now performs the step-up before any browser login, and failure branches log with stable codes.
- **Status bar overlap.** The first screenshots showed content under the Android 15 edge-to-edge status bar. Fixed with `react-native-safe-area-context`.
- **Harness and contract mistakes.** These were corrected before acceptance:
  - urllib's custom-scheme redirect handling
  - a cookie policy for Secure cookies on loopback
  - refresh-reuse semantics: the issuer correctly revokes the chain
