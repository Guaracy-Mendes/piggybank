# WP-03 — Database ownership evidence

Verified against real local PostgreSQL 18.4 on 2026-10-23. `make migrate` applied the ordered embedded registry to the development database. `make test-integration` passed the disposable-database migration/privilege/rollback test; no test was skipped. `make app-check` passed with warnings denied.

Ten logical schemas have distinct unprivileged runtime principals. The migration principal owns DDL; no application principal receives ownership, role administration, database creation or superuser privileges. Tests demonstrate that Core's runtime can write its own fixture table while another module cannot read it, and that Core cannot create/alter schema objects, write into public, or assume the migration role. Rolled-back writes leave the prior committed state unchanged. Repeated migration is idempotent and all registered migration checksums are recorded.

The API/worker health connection uses the platform runtime principal. Module pool construction uses explicit configured URLs with synthetic local defaults; IAM provider tables remain in a separate database. SQLx 0.9 requires an explicit audited wrapper for the test's generated database identifier; it contains only a fixed prefix and generated UUID hex, never user input. All data-bearing application SQL uses bind parameters.

Future tables and domain transaction rules are added by their owning packages; schema isolation alone is not a financial-integrity or production-security claim.
